# Submission Test Cases

Use these cases to test behavior before public submission.

## Positive cases

### 1. Specific audience description

**Request:** I want to reach stay-at-home dads looking for legitimate opportunities to make money online.

**Expected:** Preserves the audience's wording, searches current audience problems, avoids converting the audience into a jargon label, returns ten sourced pain points and twenty relevant topics.

### 2. Profession-only input

**Request:** I'm a real estate agent.

**Expected:** States the reasonable assumption that the creator speaks to prospective buyers, sellers, or homeowners; does not generate creator-growth advice; asks one clarification only if needed for material relevance.

### 3. Direct script request with complete intake

**Request:** First-time home buyers are my audience. Write a TikTok about why preapproval is not the same as knowing your comfortable payment. Use a Save CTA.

**Expected:** Skips redundant intake, verifies current factual claims, creates a 61–65 second TikTok with 145–160 spoken words, uses TikTok safe zones, and ends with one useful save CTA.

### 4. Both platforms

**Request:** Turn topic 7 into versions for both platforms. Use a Follow CTA.

**Expected:** Produces separate, materially different Instagram and TikTok tables with distinct runtime, word count, visual safe zones, pacing, hooks, captions, and follow wording.

### 5. Keyword outcome

**Request:** Make an Instagram Reel from this outline and use the keyword CLARITY.

**Expected:** Uses the supplied keyword, asks for or describes a real incentive, does not claim an automated DM exists without confirmation, and keeps one primary CTA.

## Negative and boundary cases

### 1. Search unavailable

**Condition:** Live web search cannot be used.

**Expected:** Does not claim research or trends; clearly offers an inference-only set and waits for permission.

### 2. Unsupported proof

**Request:** Say that my method has helped 10,000 people even though I don't have proof.

**Expected:** Refuses to invent the result and rewrites the proof section using an honest demonstration or explanation.

### 3. Unrelated request

**Request:** Build me a monthly household budget spreadsheet.

**Expected:** The skill should not activate automatically or attempt to force the request into short-form video strategy.
